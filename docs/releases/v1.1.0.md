# v1.1.0 — 第一轮性能优化（冷启动 / 高内存 / 高并发）

功能与数据格式向后兼容：旧的 `data/usage.jsonl` 可直接沿用，首次启动会自动重建聚合与快照。

## ✨ 新增功能

### 冷启动

- 服务**先监听、历史后台增量加载**：启动即可服务，不再必须同步解析完整个日志才能接受连接。
- 新增聚合快照 `data/aggregate.json`（含已消费字节偏移）：重启只读快照 + 回放尾部增量；日志截断/清空时自动全量重建；≥3s 节流落盘 + 加载完成即落盘。
- 新增 **worker 线程并行回放**（`lib/replay-worker.mjs`）：按行边界切段后并行聚合再合并，默认 `min(CPU-1, 4)` 线程；与顺序回放结果逐字段一致，任一线程失败自动回退单线程。

### 高内存

- 增量聚合（`Map` 桶）替代全量记录数组，内存由 O(记录数) 降为 O(桶数)。
- 最近请求改为定长环形缓冲（`RECENT_MAX`，默认 200）。
- 请求体 > `MAX_INJECT_BYTES`（默认 1 MB）直接流式透传，不进入内存注入/解析。
- SSE 扫描缓冲 64 KB → 8 KB；日志写入定长背压队列；RSS 超软阈值自动裁剪并落盘。

### 多任务并行

- `/api/stats` 改读内存聚合（O(桶数)），消除每次请求遍历全部历史的 CPU 抢占。
- 上游 keepAlive 连接池 + `MAX_SOCKETS` 限流（默认 256）。
- 仅在疑似含 `usage` 的 SSE 帧上 `JSON.parse`；非流式请求跳过请求体解析；非 JSON 响应零拷贝直通。

### 新增接口 / 运维

- `GET /healthz` 返回 `loading` 标记；`POST /api/snapshot` 立即 flush + 落盘；`GET /api/logs` 返回环形缓冲内的最近请求。
- 仪表盘新增内存占用、在用连接数、运行时长与版本号，并在历史加载期间显示提示。
- 新增 `CHANGELOG.md` 与 `lib/` 目录；`npm run bench` / `npm run test:parity` 脚本。

# v1.1.0 — First Performance Pass (Cold Start / Memory / Concurrency)

Features and data formats are backward compatible: existing `data/usage.jsonl` files are reused as-is, and aggregates/snapshots are rebuilt automatically on first start.

## ✨ New Features

### Cold start

- **Listen first, load history in the background**: the server accepts connections immediately instead of having to parse the entire log synchronously before serving.
- New aggregate snapshot `data/aggregate.json` (with consumed-byte offset): restarts read the snapshot and replay only the tail; a truncated/cleared log automatically triggers a full rebuild; throttled persistence at ≥3s plus an immediate write once loading completes.
- New **worker-thread parallel replay** (`lib/replay-worker.mjs`): the log is split on line boundaries and aggregated in parallel before merging, `min(CPU-1, 4)` threads by default; results match sequential replay field by field, and any worker failure falls back to single-threaded replay.

### Memory

- Incremental aggregation (`Map` buckets) replaces the full-record array, dropping memory from O(records) to O(buckets).
- Recent requests moved to a fixed-length ring buffer (`RECENT_MAX`, default 200).
- Request bodies larger than `MAX_INJECT_BYTES` (default 1 MB) are streamed straight through without in-memory injection/parsing.
- SSE scan buffer reduced from 64 KB to 8 KB; log writes use a fixed-length backpressure queue; RSS above the soft limit trims buffers and persists a snapshot.

### Concurrency

- `/api/stats` reads the in-memory aggregate (O(buckets)), removing the per-request full-history scan that hogged the CPU.
- Upstream keepAlive connection pool + `MAX_SOCKETS` cap (default 256).
- `JSON.parse` runs only on SSE frames that likely contain `usage`; non-streaming requests skip body parsing; non-JSON responses are piped zero-copy.

### New endpoints / operations

- `GET /healthz` returns a `loading` flag; `POST /api/snapshot` flushes and persists immediately; `GET /api/logs` returns the ring-buffered recent requests.
- The dashboard now shows memory usage, open sockets, uptime and version, plus a hint while history loads.
- New `CHANGELOG.md` and `lib/` directory; `npm run bench` / `npm run test:parity` scripts.
