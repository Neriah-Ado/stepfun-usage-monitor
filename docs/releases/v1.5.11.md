# v1.5.11 — 服务商 baseUrl 路径前缀 + Anthropic 协议用量解析

## 🐛 修复

### 1. 服务商 baseUrl 自带路径前缀时被丢弃（GLM / Kimi / Qwen / MiniMax 实际不可用）

- **根因**：`buildRequest` 构造上游请求时只用了 `target.hostname` 与客户端请求路径（`opts.path`），`target.pathname` 被**静默丢弃**。凡 baseUrl 自带路径的内置服务商都会打到错误的上游路径：
  - GLM：`https://open.bigmodel.cn/api/paas/v4`（OpenAI 兼容）、`https://open.bigmodel.cn/api/anthropic`（Anthropic 兼容）
  - Kimi：`https://api.moonshot.cn/v1`、Qwen：`https://dashscope.aliyuncs.com/compatible-mode/v1`、MiniMax：`https://api.minimaxi.com/v1`
  
  例：客户端请求 `/p/glm/v1/messages` → 转发到 `https://open.bigmodel.cn/v1/messages`（丢失 `/api/anthropic`）→ 被 nginx 以 **405 Not Allowed** 拒绝。
- **修复**：把 baseUrl 的路径前缀拼在请求路径之前（`pathname` 去尾斜杠后 + 请求路径）。StepFun、DeepSeek 这类 origin 级 baseUrl 行为不变。
- **接入变更（BREAKING，仅影响 v1.5.10 的绕行写法）**：客户端 Base URL **只写到 `/p/<key>`**，不要再重复拼上游路径前缀——`http://127.0.0.1:8787/p/glm` ✅ / `http://127.0.0.1:8787/p/glm/api/anthropic` ❌（修复后会把前缀拼两次）。

### 2. Anthropic 协议用量解析缺失 → 输入 tokens 记为 0

- **根因（两处叠加）**：
  1. Anthropic 的 `message_start` 事件把 usage 嵌在 `message` 对象内（`{type:"message_start","message":{…,"usage":{…}}}`），而 SSE 扫描只读顶层 `obj.usage` → 首帧 usage 被完全忽略；
  2. 流式 usage 是逐帧**覆盖**而非合并，而 Anthropic 的 `input_tokens` 在首帧（`message_start`）、`output_tokens` 终值在末帧（`message_delta`）→ 最终只留下输出 tokens，输入 tokens 汇总为 0。
- **修复**：SSE 扫描同时读取 `message.usage` / `message.model`；usage 逐帧合并后再归一化（`input_tokens → prompt_tokens`、`output_tokens → completion_tokens`）。
- **影响面**：走 `anthropic-messages` 协议的客户端（如 ZCode 的 **BigModel Coding Plan** 模板、Claude Code 风格客户端经自定义 baseUrl 接入）此前输入 tokens 全部丢失，现可正确统计。OpenAI 兼容路径行为不变（终帧 usage 本来就在顶层）。

# v1.5.11 — Provider baseUrl Path Prefix + Anthropic Protocol Usage Parsing

## 🐛 Fixes

### 1. The path prefix of a provider baseUrl was dropped (GLM / Kimi / Qwen / MiniMax were effectively unusable)

- **Root cause**: `buildRequest` built the upstream request from `target.hostname` plus the client request path (`opts.path`) only — `target.pathname` was **silently discarded**. Every built-in provider whose baseUrl carries a path therefore hit the wrong upstream path:
  - GLM: `https://open.bigmodel.cn/api/paas/v4` (OpenAI-compatible) and `https://open.bigmodel.cn/api/anthropic` (Anthropic-compatible)
  - Kimi: `https://api.moonshot.cn/v1`, Qwen: `https://dashscope.aliyuncs.com/compatible-mode/v1`, MiniMax: `https://api.minimaxi.com/v1`

  Example: a client request to `/p/glm/v1/messages` was forwarded to `https://open.bigmodel.cn/v1/messages` (dropping `/api/anthropic`) → rejected by nginx with **405 Not Allowed**.
- **Fix**: the baseUrl path prefix is now prepended to the request path (`pathname` with trailing slashes trimmed + request path). Origin-level baseUrls (StepFun, DeepSeek) behave exactly as before.
- **Migration (BREAKING, affects only the v1.5.10 workaround)**: set the client Base URL to `/p/<key>` **only** — do not repeat the upstream path prefix: `http://127.0.0.1:8787/p/glm` ✅ / `http://127.0.0.1:8787/p/glm/api/anthropic` ❌ (the prefix would be applied twice).

### 2. Anthropic protocol usage parsing was missing → input tokens recorded as 0

- **Root cause (two compounding issues)**:
  1. Anthropic's `message_start` event nests usage inside `message` (`{type:"message_start","message":{…,"usage":{…}}}`), while the SSE scanner only read top-level `obj.usage` → the first frame's usage was ignored entirely;
  2. streaming usage was **replaced** frame-by-frame instead of merged, and Anthropic puts `input_tokens` in the first frame (`message_start`) and the final `output_tokens` in the last one (`message_delta`) → only output tokens survived, with input tokens aggregating to 0.
- **Fix**: the SSE scanner now also reads `message.usage` / `message.model`, and usage frames are merged before normalization (`input_tokens → prompt_tokens`, `output_tokens → completion_tokens`).
- **Impact**: clients speaking the `anthropic-messages` protocol (e.g. ZCode's **BigModel Coding Plan** template, Claude Code-style clients via a custom baseUrl) previously lost all input tokens and now count correctly. The OpenAI-compatible path is unchanged (its terminal-frame usage is top-level anyway).

- New `test/anthropic-usage-check.mjs` (`npm run test:anthropic`): spins up a mock upstream (Anthropic-compatible endpoint carrying an `/api/anthropic` path prefix) plus a proxy subprocess, with **7 assertions**:

- Runs entirely locally — **no network, no API quota consumed**; results are written to `test/anthropic-result.txt` (for environments without stdout).
