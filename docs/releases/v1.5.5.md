# v1.5.5 — 多服务商支持 + 服务商一键切换

## ✨ 新增功能

### 1. 多服务商支持（一个代理实例服务多家大模型）

- 内置 7 家 OpenAI 兼容服务商：**StepFun 阶跃星辰 / 智谱 GLM / DeepSeek / Kimi Moonshot / MiniMax / 通义千问 Qwen / 零一万物 Yi**。
- 支持自定义服务商：在数据目录放置 `providers.json`，可添加任意 OpenAI 兼容网关，也可按 key 覆盖内置服务商的 `baseUrl` / `apiKey` / `modelPrefixes`。

### 2. 四级路由优先级（前一级命中即不再向下匹配）

| 优先级 | 方式 | 示例 |
|---|---|---|
| 1 | 路径前缀 `/p/<key>/v1/...`（转发时自动剥除前缀） | `/p/deepseek/v1/chat/completions` |
| 2 | 请求头 `X-Provider: <key>` | 适合不方便改路径的客户端 |
| 3 | 模型名前缀命中服务商 `modelPrefixes` | `deepseek-chat` → deepseek |
| 4 | 激活默认（仪表盘一键切换或 `POST /api/provider`） | 默认 StepFun |

- 路径前缀 / 请求头 / 切换请求指定了未知 key 时返回 **400 + 合法服务商列表**，不会静默落到默认服务商。

### 3. 密钥按服务商注入

客户端未带 `Authorization` 时，按 `providers.json` 内的 `apiKey` > 环境变量 的顺序注入。各服务商环境变量：`STEPFUN_API_KEY` / `GLM_API_KEY`（或 `BIGMODEL_API_KEY`）/ `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY`（或 `KIMI_API_KEY`）/ `MINIMAX_API_KEY` / `DASHSCOPE_API_KEY` / `YI_API_KEY`。`TARGET_URL` 仍可覆盖 StepFun 的 baseUrl（v1.5.5 之前的用法保持有效）。

### 4. 仪表盘服务商切换器（一键切换，无需复杂操作）

- 顶栏新增服务商切换器：点击 → 选择 → 即切换（乐观 UI，失败自动回滚）；激活项持久化到 `providers.json`，重启不丢失。
- 新增**服务商用量表面板**：按服务商分组的请求数与 token 统计。
- 页脚实时显示当前服务商与上游地址。
- 布局自适应：底栏布局自动隐藏切换器，小窗布局自动隐藏服务商表。

### 5. 统计与查询

- `usage.jsonl` 每条记录新增 `provider` 字段（旧记录自动归入 stepfun，向后兼容）。
- `GET /api/stats` 新增 `byProvider` 分组与 `meta.provider` / `meta.providers`。
- MCP 工具 `query_stepfun_usage` 的 `group` 参数新增 `provider` 选项。
- 新增接口：`GET /api/providers`（服务商列表，不含任何密钥）、`POST /api/provider`（切换激活服务商）。

### 6. 其他

- VSIX 扩展重建为 `stepfun-monitor-1.5.5.vsix`（适配多服务商仪表盘）。
- 并行回放（worker 线程）按服务商聚合，冷启动统计与单线程回放逐字段一致。

## 🐛 修复

- **升级路径快照兼容**：v1.5.0 及更早版本写入的 `aggregate.json` 快照不含 `byProvider` 字段，直接沿用会导致服务商分组统计为空。现仅信任 v3+ 快照；对「请求数 > 0 但 byProvider 为空」的损坏快照自动全量回放重建（一次性开销，之后恢复正常快照路径）。

# v1.5.5 — Multi-Provider Support with One-Click Switching

## ✨ New Features

### 1. Multi-provider support (one proxy instance, many LLM providers)

- 7 built-in OpenAI-compatible providers: **StepFun, Zhipu GLM, DeepSeek, Kimi (Moonshot), MiniMax, Qwen (DashScope), Yi (01.AI)**.
- Custom providers: drop a `providers.json` in the data directory to add any OpenAI-compatible gateway, or override a built-in provider's `baseUrl` / `apiKey` / `modelPrefixes` by key.

### 2. Four-level routing priority (first match wins)

| Priority | Method | Example |
|---|---|---|
| 1 | Path prefix `/p/<key>/v1/...` (prefix stripped when forwarding) | `/p/deepseek/v1/chat/completions` |
| 2 | Request header `X-Provider: <key>` | for clients that cannot change the path |
| 3 | Model-name prefix matching the provider's `modelPrefixes` | `deepseek-chat` → deepseek |
| 4 | Active default (dashboard one-click switch or `POST /api/provider`) | StepFun by default |

- An unknown key given via path prefix / header / switch request returns **400 + the list of valid providers** instead of silently falling back to the default provider.

### 3. Per-provider key injection

When the client sends no `Authorization` header, the proxy injects a key in the order `providers.json` apiKey > environment variable. Env vars: `STEPFUN_API_KEY` / `GLM_API_KEY` (or `BIGMODEL_API_KEY`) / `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY` (or `KIMI_API_KEY`) / `MINIMAX_API_KEY` / `DASHSCOPE_API_KEY` / `YI_API_KEY`. `TARGET_URL` still overrides StepFun's baseUrl (usage from before v1.5.5 remains valid).

### 4. Dashboard provider switcher (one click, no complex setup)

- New switcher in the top bar: click → pick → done (optimistic UI with automatic rollback on failure). The active provider persists to `providers.json` and survives restarts.
- New **provider usage panel**: requests and tokens grouped by provider.
- The footer shows the current provider and upstream origin in real time.
- Layout-aware: the switcher is hidden in the bottom-bar layout; the provider table is hidden in the small-window layout.

### 5. Stats & queries

- Every `usage.jsonl` record gains a `provider` field (legacy records are attributed to stepfun — backward compatible).
- `GET /api/stats` gains the `byProvider` breakdown plus `meta.provider` / `meta.providers`.
- The MCP tool `query_stepfun_usage` accepts `group="provider"`.
- New endpoints: `GET /api/providers` (provider list, never includes keys) and `POST /api/provider` (switch the active provider).

### 6. Misc

- VSIX extension rebuilt as `stepfun-monitor-1.5.5.vsix` (multi-provider dashboard).
- Parallel replay (worker threads) aggregates by provider; cold-start stats match single-threaded replay field by field.

## 🐛 Fixes

- **Upgrade-path snapshot compatibility**: snapshots written by v1.5.0 and earlier (`aggregate.json`) contain no `byProvider` field; reusing them directly left the per-provider stats empty. Only v3+ snapshots are trusted now, and a corrupt snapshot ("requests > 0 but byProvider empty") triggers an automatic full replay rebuild (one-time cost; the fast snapshot path resumes afterwards).
