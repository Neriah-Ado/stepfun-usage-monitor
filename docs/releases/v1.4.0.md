# v1.4.0 — 交互性能优化 + 轻量 / 进阶 / 极致 3 档性能模式

## ✨ 新增功能

### 1. 降低点击响应延迟

- **乐观 UI**：点击「提示」按钮或提示词芯片时，按钮变绿与 Toast 反馈同步立即执行，剪贴板写入等异步动作全部后置；仅在真正失败时才回滚为红色错误提示。
- **单飞（single-flight）请求**：手动刷新与轮询共用同一次在途请求，杜绝并发请求互相抢占事件循环。
- **渲染让帧**：数据到达后先经 `requestAnimationFrame` 让出一帧再执行 DOM 更新，点击等交互永远优先响应。
- **档位切换零延迟**：性能档位通过 `html[data-perf]` 属性同步写入，CSS 立即重建样式，不等待任何请求往返。

### 2. 提升交互性能（渲染路径重写）

- **一次性骨架 + 原地增量更新**：`#app` 不再整段 `innerHTML` 重建，骨架只挂载一次，后续仅写入变化的文本、条宽与 SVG 节点。
- **数据签名短路**：每次刷新计算数据签名，数据未变化时零 DOM 操作（仅更新「更新于」时间戳）。
- **分表独立签名短路**：模型排行 / 客户端排行 / 最近请求各自独立签名，互不牵连重绘。
- **图表按需重算**：SVG 字符串只在每日序列变化时才重新构造。
- **数字更新零开销**：`setNum()` 在数值未变时直接返回，不触发任何 DOM 写入与动画。
- **限定重排范围**：卡片与面板加 `contain: content`；最近请求面板使用 `content-visibility: auto` 跳过屏外渲染。

### 3. 新增卡顿等待动画

- **首屏骨架屏**：加载中数值位显示 shimmer 骨架，替代空白闪烁。
- **顶部不确定进度条**：仅当请求超过 350 ms（即真正出现「卡顿」）才出现，避免快请求时进度条闪烁的视觉噪声。
- **同步指示**：请求进行中在档位栏显示「同步中…」微指示。
- **轻量档降级**：以上动效在「轻量」档全部禁用，退化为纯文本提示（零动画开销）。
- **尊重系统设置**：`prefers-reduced-motion: reduce` 时，即使选择「极致」档也关闭全部动效。

### 4. 新增 3 档性能模式

档位栏位于 `#app` 之外（自动刷新不会重建），选择持久化于 `localStorage['sfm:perf']`，支持键盘 ←/→ 切换。

| | 轻量 | 进阶（默认） | 极致 |
|---|---|---|---|
| 轮询间隔 | **120 s** | 30 s | **10 s** |
| 数据载荷 | **`?lite=1` 精简** | 完整 | 完整 |
| 图表 | **不绘制 SVG**，仅文字摘要 | 完整柱状图 | 完整柱状图 |
| 排行榜 / 最近请求行数 | 5 / 6 | 8 / 10 | 12 / 20 |
| 动画 / 过渡 / 阴影 / 渐变 | **全部关闭** | 轻量过渡 | 数字滚动 + 入场 + 数值高亮 |
| 页面隐藏时 | **暂停轮询** | 暂停轮询 | 暂停轮询 |

此外，以下优化在**所有档位**生效：

- **页面隐藏即暂停**：`visibilitychange` 时清除定时器，回到前台且数据过期才立即补拉——后台标签页零轮询、零 CPU。
- **`setTimeout` 链替代 `setInterval`**：慢请求不会造成定时器堆叠。
- **离线暂停**：`offline` 事件时暂停轮询并给出提示。
- **新增手动「刷新」按钮**。

### 5. 代理端

- `GET /api/stats?lite=1` 精简载荷（`byModel`/`byAgent` 各 5 条、`recent` 6 条、天数上限 14），`meta.mode = "lite"`。
- 新增 `meta.ts` 服务端时间戳。
- `/favicon.ico` 与 `/robots.txt` 改为本地 204 应答，不再转发到上游。

## 🐛 修复

- `<svg>` 属 `SVGElement`，没有 `hidden` IDL 属性——`svg.hidden = true` 只挂了个 JS expando，属性未落到 DOM，导致轻量档图表隐藏后留下大片空白；现统一改走 `setAttribute('hidden')`。
- `#chart-svg{display:block}` 等组件样式会覆盖 UA 的 `[hidden]{display:none}`，导致轻量档图例与图表未真正隐藏；现全局补 `[hidden]{display:none!important}`。

# v1.4.0 — Interaction Performance + Lite / Balanced / Ultra Modes

## ✨ New Features

### 1. Lower click-response latency

- **Optimistic UI**: clicking the hint button or the prompt chip turns the button green and shows the toast synchronously; async work such as clipboard writes is deferred. A red error toast appears only on genuine failure.
- **Single-flight requests**: manual refresh and polling share one in-flight request, preventing concurrent requests from fighting over the event loop.
- **Frame-yielding rendering**: DOM updates run after a `requestAnimationFrame` yield, so clicks always respond first.
- **Zero-latency mode switching**: the performance mode is written synchronously via the `html[data-perf]` attribute, so CSS rebuilds immediately with no request round-trip.

### 2. Faster interaction (rendering path rewrite)

- **One-time skeleton + in-place incremental updates**: `#app` is no longer rebuilt with a full `innerHTML`; the skeleton mounts once, afterwards only changed text, bar widths and SVG nodes are written.
- **Data-signature short-circuit**: a signature is computed on every refresh; when nothing changed, zero DOM operations run (only the "updated at" timestamp).
- **Per-table signatures**: model ranking / client ranking / recent requests each have independent signatures, so one table never forces another to repaint.
- **On-demand chart rebuild**: the SVG string is reconstructed only when the daily series changes.
- **Zero-cost number updates**: `setNum()` returns immediately when the value is unchanged — no DOM write, no animation.
- **Contained reflow**: `contain: content` on cards and panels; the recent-requests panel uses `content-visibility: auto` to skip off-screen rendering.

### 3. New stall-wait animations

- **First-paint skeleton**: shimmer placeholders while loading instead of a blank flash.
- **Top indeterminate progress bar**: appears only when a request exceeds 350 ms (a real stall), avoiding flicker on fast requests.
- **Sync indicator**: a subtle "syncing…" hint in the mode bar while a request is in flight.
- **Lite-mode degradation**: all of the above animations are disabled in Lite mode, degrading to plain text (zero animation cost).
- **Respects system settings**: with `prefers-reduced-motion: reduce`, all animations are off even in Ultra mode.

### 4. New 3-tier performance modes

The mode bar lives outside `#app` (auto-refresh never rebuilds it), the choice persists in `localStorage['sfm:perf']`, and ←/→ keys switch modes.

| | Lite | Balanced (default) | Ultra |
|---|---|---|---|
| Poll interval | **120 s** | 30 s | **10 s** |
| Payload | **`?lite=1` slim** | Full | Full |
| Chart | **No SVG**, text summary only | Full bar chart | Full bar chart |
| Ranking / recent rows | 5 / 6 | 8 / 10 | 12 / 20 |
| Animations / transitions / shadows / gradients | **All off** | Light transitions | Number roll-up + entrance + value highlight |
| When page hidden | **Polling paused** | Polling paused | Polling paused |

In addition, the following apply in **all modes**:

- **Pause when hidden**: timers are cleared on `visibilitychange`; an immediate refetch happens only on return when data is stale — background tabs cost zero polling and zero CPU.
- **`setTimeout` chain instead of `setInterval`**: slow requests no longer stack up timers.
- **Offline pause**: polling pauses with a hint on the `offline` event.
- **New manual "Refresh" button**.

### 5. Proxy side

- `GET /api/stats?lite=1` slim payload (`byModel`/`byAgent` 5 entries each, `recent` 6, max 14 days) with `meta.mode = "lite"`.
- New `meta.ts` server timestamp.
- `/favicon.ico` and `/robots.txt` are now answered locally with 204 instead of being forwarded upstream.

## 🐛 Fixes

- `<svg>` is an `SVGElement` and has **no `hidden` IDL property** — `svg.hidden = true` only attached a JS expando without reflecting to the DOM, leaving a large blank area after the Lite-mode chart was hidden; everything now goes through `setAttribute('hidden')`.
- Component styles such as `#chart-svg{display:block}` overrode the UA's `[hidden]{display:none}`, so the Lite-mode legend and chart were not truly hidden; a global `[hidden]{display:none!important}` rule was added.
