# v1.5.10 — ZCode 插件安装后自包含（修复 /sfm 无法调出插件）

## 🐛 修复

### 1. ZCode 安装插件后 `/sfm` 无法调出插件（MCP 服务器启动失败）

- **根因**：ZCode 安装插件 zip 时**只解压插件目录本身**（落到 `cache/zcode-plugins-official/<name>/<version>/`，内含 `.zcode-plugin/`、`commands/`、`.mcp.json` 等），**不含仓库根文件**。v1.5.9 的 `.mcp.json` 通过 `${CLAUDE_PLUGIN_ROOT}/../../bin/cli.mjs` 引用仓库根统一入口，安装后 `../../` 指向不存在的位置 → MCP 服务器无法启动 → `/sfm` 命令内的工具调用全部失败。
- **修复**：新增 `plugins/stepfun-usage-monitor/runtime/` **自包含目录**——`bin/cli.mjs`、`proxy.mjs`、`mcp-server.mjs`、`stats.mjs`、`dashboard.html`、`package.json`、`lib/` 全部运行文件内置其中，与仓库根**逐字节一致**（由 `test/sync-plugin-runtime.mjs` 同步并校验）；`.mcp.json` 改为指向 `${CLAUDE_PLUGIN_ROOT}/runtime/bin/cli.mjs --mcp`，安装后路径立即可解析，MCP 服务器直接可启动。

## ✨ 新增功能

### 1. runtime 同步脚本与自包含校验

- 新增 `test/sync-plugin-runtime.mjs`：一键把仓库运行文件同步进插件 `runtime/`，含逐字节一致性校验、`RUNTIME-INFO.txt` 版本标记、`runtime cli --version` 快检；根文件更新后重跑一次即可，杜绝漏同步。
- `test/v15-check.mjs` 新增 0c 节断言：`runtime/` 含全部 10 个运行文件且与仓库根逐字节一致；`.mcp.json` 必须指向 `${CLAUDE_PLUGIN_ROOT}/runtime/bin/cli.mjs`。
- `test/mcp-test.mjs` / `test/npm-pack-check.mjs` 新增**插件安装态 MCP 断言**：直接运行 `plugins/*/runtime/bin/cli.mjs --mcp`（及 npm tarball 安装后的同路径），`initialize` + `tools/list` 全通过——即 ZCode 安装后的真实入口。

### 2. plugin.json 对齐官方字段

- `.zcode-plugin/plugin.json` 新增 `description_i18n`（`en` / `zh-CN`），与 [ZCode 插件官方规范](https://zcode.z.ai/cn/docs/plugin)的 plugin.json 字段对齐。

### 3. 版本号统一升级

- `package.json` / `proxy.mjs` / `mcp-server.mjs` / `ide-extension` / `marketplace.json` / `plugin.json` 全部升级为 1.5.10；VSIX 重建为 `stepfun-monitor-1.5.10.vsix`。

# v1.5.10 — Self-Contained ZCode Plugin After Install (fixes /sfm not raising the plugin)

## 🐛 Fixes

### 1. `/sfm` did nothing after installing the ZCode plugin (MCP server failed to start)

- **Root cause**: when ZCode installs a plugin zip it unpacks **only the plugin directory itself** (into `cache/zcode-plugins-official/<name>/<version>/`, containing `.zcode-plugin/`, `commands/`, `.mcp.json`, etc.) — **repo-root files are not included**. v1.5.9's `.mcp.json` pointed at the repo-root entry via `${CLAUDE_PLUGIN_ROOT}/../../bin/cli.mjs`; after install, `../../` resolves to a nonexistent location → the MCP server never starts → every tool call behind `/sfm` fails.
- **Fix**: new self-contained `plugins/stepfun-usage-monitor/runtime/` directory — `bin/cli.mjs`, `proxy.mjs`, `mcp-server.mjs`, `stats.mjs`, `dashboard.html`, `package.json` and `lib/` are all bundled inside, **byte-identical** to the repo root (synced and verified by `test/sync-plugin-runtime.mjs`); `.mcp.json` now points at `${CLAUDE_PLUGIN_ROOT}/runtime/bin/cli.mjs --mcp`, which resolves correctly after install so the MCP server starts directly.

## ✨ New Features

### 1. Runtime sync script and self-containment checks

- New `test/sync-plugin-runtime.mjs`: one command syncs the repo's runtime files into the plugin's `runtime/`, with byte-for-byte verification, a `RUNTIME-INFO.txt` version marker, and a `runtime cli --version` smoke check. Re-run it after any root-file change.
- `test/v15-check.mjs` gains a 0c section: `runtime/` must contain all 10 runtime files byte-identical to the repo root, and `.mcp.json` must point at `${CLAUDE_PLUGIN_ROOT}/runtime/bin/cli.mjs`.
- `test/mcp-test.mjs` / `test/npm-pack-check.mjs` gain **installed-plugin MCP assertions**: they run `plugins/*/runtime/bin/cli.mjs --mcp` directly (and the same path inside the installed npm tarball) with `initialize` + `tools/list` — i.e. the exact entry ZCode uses after install.

### 2. plugin.json aligned with official fields

- `.zcode-plugin/plugin.json` gains `description_i18n` (`en` / `zh-CN`), matching the plugin.json fields of the [official ZCode plugin spec](https://zcode.z.ai/cn/docs/plugin).

### 3. Unified version bump

- `package.json` / `proxy.mjs` / `mcp-server.mjs` / `ide-extension` / `marketplace.json` / `plugin.json` all bumped to 1.5.10; VSIX rebuilt as `stepfun-monitor-1.5.10.vsix`.
